# CompTIA Security+ (SY0-701) Bilingual Study Plan

> **English Centered study with Portuguese support annotations.**

## 8-Week Rigorous Preparation Schedule

### Week 1: General Security Concepts & Core Basics
**Semana 1: Conceitos Gerais de Segurança e Fundamentos**

- **Focus Domains:** Domain 1.0: General Security Concepts (12%)
- **Chapters Covered:** Chapter 1: Mastering Security Basics, Chapter 11: Implementing Policies to Mitigate Risks (Change Management & Data Protection)

#### Weekly Objective / Objetivo
Understand the core goals of information security (CIA triad), differentiate between security control categories and types, and comprehend the importance of change management and data classification.

#### Daily Study Schedule / Cronograma Diario

- **Monday:** Read Chapter 1: Mastering Security Basics (Security goals: CIA, non-repudiation, AAA).
- **Tuesday:** Study Chapter 1 Security Controls (Categories: Technical, Managerial, Operational, Physical; and Types: Preventive, Deterrent, Detective, Corrective, Compensating, Directive).
- **Wednesday:** Read Chapter 11: Change Management & Data Protection (Data types, classification, sanitization, change approval, backout plan).
- **Thursday:** Active recall: Review Week 1 Flashcards and create your own mind map of control types in Portuguese.
- **Friday:** Practice Quiz: Solve Chapter 1 & Chapter 11 end-of-chapter questions (English) and study the Portuguese explanations.
- **Saturday:** Weekly Review: Consolidate the bilingual glossary of key terms. Study the 'Golden Rules' for Change Management.
- **Sunday:** Rest day / Catch-up day.

#### Bilingual Key Glossary

| Term (English) | Traducao | Definition / Descricao |
| :--- | :--- | :--- |
| **Confidentiality** | Confidencialidade | Ensures that unauthorized entities cannot access sensitive data (encryption, access controls). |
| **Integrity** | Integridade | Ensures that data has not been modified, tampered with, or corrupted (hashing, digital signatures). |
| **Availability** | Disponibilidade | Ensures systems and data are accessible when needed by authorized users (redundancy, backups). |
| **Technical Control** | Controle Técnico | Controls implemented using technology (firewalls, encryption, antivirus). |
| **Managerial Control** | Controle Administrativo/Gerencial | Controls using administrative methods, policies, risk assessments, and training. |
| **Operational Control** | Controle Operacional | Controls executed by people in daily routines (media restoration, incident response). |
| **Physical Control** | Controle Físico | Controls that physically block access (fences, locks, security guards, barricades). |
| **Change Management** | Gestão de Mudanças | Structured process to request, evaluate, approve, and implement system modifications safely. |

### Week 2: Identity and Access Management (IAM)
**Semana 2: Gestão de Identidade e Acesso (IAM)**

- **Focus Domains:** Domain 1.0: General Security Concepts, Domain 2.0: Threats, Vulnerabilities, and Mitigations
- **Chapters Covered:** Chapter 2: Understanding Identity and Access Management

#### Weekly Objective / Objetivo
Master authentication factors (MFA, passwordless), account management policies, privileged access management (PAM), single sign-on (SSO), and access control authorization models.

#### Daily Study Schedule / Cronograma Diario

- **Monday:** Read Chapter 2: Identification, AAA, and Authentication Factors (Something you know, have, are, somewhere you are, something you do).
- **Tuesday:** Study MFA, Passwordless authentication, and Authentication Log Files/Indicators.
- **Wednesday:** Study Account Management Policies (credential policies, PAM, deprovisioning, role-based vs group-based, shared account prohibition).
- **Thursday:** Study Single Sign-On (SSO), Federation (SAML, OAuth) and directory services (LDAP).
- **Friday:** Study Authorization Models: Role-Based (RBAC), Rule-Based, Discretionary (DAC), Mandatory (MAC - labels/lattice), and Attribute-Based (ABAC).
- **Saturday:** Weekly Review: Practice Week 2 Flashcards & Chapter 2 quiz questions. Focus on distinguishing SAML (authentication) from OAuth (authorization).
- **Sunday:** Rest day / Catch-up day.

#### Bilingual Key Glossary

| Term (English) | Traducao | Definition / Descricao |
| :--- | :--- | :--- |
| **Multifactor Authentication (MFA)** | Autenticação de Múltiplos Fatores | Requiring two or more distinct factors (e.g., password + hardware token). |
| **Privileged Access Management (PAM)** | Gestão de Acessos Privilegiados | Securing and monitoring highly elevated administrative credentials. |
| **Federation / SSO** | Federação / Single Sign-On | Allows users to log in once and access resources across multiple independent systems/domains. |
| **SAML** | Security Assertion Markup Language | XML-based open standard for exchanging authentication and authorization data. |
| **OAuth** | OAuth (Open Authorization) | Token-based authorization protocol used for secure API authorization (delegated access). |
| **Discretionary Access Control (DAC)** | Controle de Acesso Discricionário | Data owners determine who has access (used in standard filesystems with NTFS/ext4 permissions). |
| **Mandatory Access Control (MAC)** | Controle de Acesso Mandatório | Access is based on security labels and classification levels (military grade, lattice model). |
| **Attribute-Based Access Control (ABAC)** | Controle de Acesso Baseado em Atributos | Flexible access control based on user, resource, and environmental attributes (time, location). |

### Week 3: Network Infrastructure, Protocols and Security
**Semana 3: Infraestrutura, Protocolos e Segurança de Rede**

- **Focus Domains:** Domain 3.0: Security Architecture, Domain 4.0: Security Operations
- **Chapters Covered:** Chapter 3: Exploring Network Technologies and Tools, Chapter 4: Securing Your Network

#### Weekly Objective / Objetivo
Analyze secure network protocols, design, and appliances. Master firewalls, switches, routers, IDS/IPS, honeypots, wireless security (WPA3), VPNs, and network access control (NAC).

#### Daily Study Schedule / Cronograma Diario

- **Monday:** Read Chapter 3: OSI Model, Secure network protocols mapping (HTTPS, SSH, SFTP, DNSSEC, SNMPv3, SRTP).
- **Tuesday:** Study network infrastructure hardening (switches, routers, firewalls, screened subnets, jump servers).
- **Wednesday:** Study Zero Trust concepts (control plane vs. data plane, SASE, secure access service edge).
- **Thursday:** Read Chapter 4: IDS vs. IPS (signature vs. anomaly), honeypots, honeyfiles, honeytokens.
- **Friday:** Study wireless security (WPA2/WPA3 Personal vs. Enterprise, 802.1x), VPN topologies (Full vs Split, Site-to-site, Always-On), and NAC (Agent vs Agentless).
- **Saturday:** Weekly Review: Practice Week 3 Quizzes and Flashcards. Draw a secure network topology with a Screened Subnet and a Jump Server.
- **Sunday:** Rest day / Catch-up day.

#### Bilingual Key Glossary

| Term (English) | Traducao | Definition / Descricao |
| :--- | :--- | :--- |
| **Screened Subnet (DMZ)** | Sub-rede Protegida / DMZ | Buffer zone between the untrusted internet and internal private network containing public-facing servers. |
| **Secure Access Service Edge (SASE)** | SASE | Cloud architecture merging software-defined wide area networking (SD-WAN) with comprehensive cloud security functions (CASB, FWaaS, ZTNA). |
| **Honeypot** | Honeypot (Pote de Mel) | Decoy system designed to attract and analyze attacker behavior in a controlled environment. |
| **WPA3** | WPA3 | Latest wireless security protocol replacing WPA2, using SAE (Simultaneous Authentication of Equals) to protect against offline dictionary attacks. |
| **Split Tunnel** | Túnel Dividido | VPN configuration where only corporate-destined traffic goes through the encrypted tunnel; general internet traffic goes directly. |
| **Network Access Control (NAC)** | Controle de Acesso à Rede | Inspects host health (patches, antivirus, firewall status) before granting network access. |
| **SNMPv3** | SNMPv3 | Secure network management protocol that provides encryption, authentication, and message integrity. |

### Week 4: Host, Cloud, Data Security & Cryptography
**Semana 4: Segurança de Hosts, Nuvem, Dados e Criptografia**

- **Focus Domains:** Domain 3.0: Security Architecture, Domain 1.0: General Security Concepts
- **Chapters Covered:** Chapter 5: Securing Hosts and Data, Chapter 10: Understanding Cryptography and PKI

#### Weekly Objective / Objetivo
Grasp virtualization, containerization, and cloud security frameworks (CASB, IaC, Shared Responsibility). Master cryptography concepts (symmetric, asymmetric, hashing, digital signatures, PKI, CA, CRL, OCSP).

#### Daily Study Schedule / Cronograma Diario

- **Monday:** Read Chapter 5: Virtualization, Containerization, secure systems (endpoint security, CSP responsibility, IaC).
- **Tuesday:** Study mobile device security deployment models (BYOD, COPE) and MDM capabilities.
- **Wednesday:** Study specialized/embedded systems security (IoT, ICS/SCADA) and cryptographic data protection (TPM, HSM, secure enclaves, obfuscation).
- **Thursday:** Read Chapter 10: Cryptography foundations (hashing algorithms, salting, symmetric vs asymmetric encryption).
- **Friday:** Study Public Key Infrastructure (PKI): Private/Public key pairs, CA, CRL, OCSP, CSR, certificate pinning, and formats.
- **Saturday:** Weekly Review: Quiz on host security & cryptography. Practice 'Golden Rules' (e.g. Asymmetric encryption: Private key decrypts / signs; Public key encrypts / verifies).
- **Sunday:** Rest day / Catch-up day.

#### Bilingual Key Glossary

| Term (English) | Traducao | Definition / Descricao |
| :--- | :--- | :--- |
| **Cloud Access Security Broker (CASB)** | CASB | On-premises or cloud-based security enforcement point placed between cloud service consumers and providers to enforce security policies. |
| **Infrastructure as Code (IaC)** | Infraestrutura como Código | Managing and provisioning infrastructure through machine-readable definition files, ensuring consistency and automation. |
| **Trusted Platform Module (TPM)** | TPM | Dedicated cryptographic hardware chip integrated on a computer motherboard to secure hardware assets via keys. |
| **Symmetric Encryption** | Criptografia Simétrica | Uses a single, shared secret key for both encryption and decryption (AES, DES). |
| **Asymmetric Encryption** | Criptografia Assimétrica | Uses a mathematically linked key pair: a public key (for encryption/verification) and a private key (for decryption/signing). |
| **Certificate Authority (CA)** | Autoridade Certificadora | Trusted third-party organization that issues digital certificates, verifying the identity of entities. |
| **Online Certificate Status Protocol (OCSP)** | Protocolo de Status de Certificado Online | Real-time query protocol used to check the revocation status of an X.509 digital certificate. |

### Week 5: Threats, Vulnerabilities and Common Attacks
**Semana 5: Ameaças, Vulnerabilidades e Ataques Comuns**

- **Focus Domains:** Domain 2.0: Threats, Vulnerabilities, and Mitigations (22%)
- **Chapters Covered:** Chapter 6: Comparing Threats, Vulnerabilities, and Common Attacks

#### Weekly Objective / Objetivo
Examine threat actors, attributes, motivations, threat vectors, and attack surfaces. Differentiate between types of malware and master human-based social engineering attacks.

#### Daily Study Schedule / Cronograma Diario

- **Monday:** Read Chapter 6: Threat Actors (Nation-state, unskilled, hacktivist, insider, organized crime) and their motivations (espionage, financial gain).
- **Tuesday:** Study Threat Vectors (message, image, file, voice, removable device) and Attack Surfaces (vulnerable software, unsupported apps, shadow IT).
- **Wednesday:** Study Malware Types (Viruses, Worms, Logic Bombs, Trojans, RATs, Keyloggers, Spyware, Rootkits, Ransomware, Bloatware).
- **Thursday:** Study Malware Indicators (performance degradation, unauthorized modifications) and detection methods.
- **Friday:** Study Social Engineering (Impersonation, Shoulder Surfing, Disinformation, Tailgating, Dumpster Diving, Watering Hole, Phishing, Vishing, Smishing).
- **Saturday:** Weekly Review: Quiz on threats & malware. Memorize the difference between Virus (needs human interaction to execute) and Worm (self-replicating, spreads over network).
- **Sunday:** Rest day / Catch-up day.

#### Bilingual Key Glossary

| Term (English) | Traducao | Definition / Descricao |
| :--- | :--- | :--- |
| **Shadow IT** | TI Invisível / Shadow IT | Information technology systems, devices, or software used within an organization without explicit IT department approval. |
| **Remote Access Trojan (RAT)** | Cavalo de Troia de Acesso Remoto | Malware that gives an attacker administrative control over a target system through a backdoor. |
| **Rootkit** | Rootkit | Malicious software designed to hide its existence and other malware from OS detection tools by operating at deep kernel levels. |
| **Watering Hole Attack** | Ataque de Watering Hole (Poço de Água) | Targeting a specific group of users by infecting a website they are known to visit frequently. |
| **Disinformation** | Desinformação | Deliberately false or distorted information spread systematically to deceive, mislead, or cause chaos (increasingly AI-driven). |
| **Insider Threat** | Ameaça Interna | A security threat originating from within the organization (employees, contractors) who have authorized access to systems. |

### Week 6: Advanced Attacks, Secure Coding & Risk Management
**Semana 6: Ataques Avançados, Código Seguro e Gestão de Riscos**

- **Focus Domains:** Domain 2.0: Threats, Vulnerabilities, and Mitigations, Domain 4.0: Security Operations
- **Chapters Covered:** Chapter 7: Protecting Against Advanced Attacks, Chapter 8: Using Risk Management Tools

#### Weekly Objective / Objetivo
Analyze advanced network attacks (DoS, DNS poisoning, on-path). Understand secure coding concepts, application vulnerabilities (buffer overflow, injections, XSS). Master risk management tools, framework standards (NIST, ISO), and audits.

#### Daily Study Schedule / Cronograma Diario

- **Monday:** Read Chapter 7: Network Attacks (SYN floods, On-path, SSL stripping, DNS poisoning, Domain hijacking, Replay).
- **Tuesday:** Study Secure Coding Concepts (input validation, error handling, race conditions, obfuscation, HTTP headers, secure cookies, code signing).
- **Wednesday:** Study Application Attacks (Memory leaks, Buffer overflows, SQL injection, DLL/LDAP/XML injection, Directory traversal, XSS, CSRF) and Automation/Scripting in Ops.
- **Thursday:** Read Chapter 8: Risk Management basics (vulnerability scanning, validation of remediation).
- **Friday:** Study Network Traffic Tools (packet captures, tcpdump, tcpreplay, NetFlow) and Compliance Frameworks (ISO 27001, NIST CSF 2.0, NIST RMF, benchmarks).
- **Saturday:** Weekly Review: Practice advanced attacks and frameworks quiz. Focus on how input validation prevents injections and how parameterization secures databases.
- **Sunday:** Rest day / Catch-up day.

#### Bilingual Key Glossary

| Term (English) | Traducao | Definition / Descricao |
| :--- | :--- | :--- |
| **On-Path Attack (MitM)** | Ataque On-Path / Homem no Meio | Attacker intercepts and silently alters communications between two trusting systems. |
| **DNS Poisoning** | Envenenamento de DNS | Corrupting Domain Name System cache to redirect users to malicious IP addresses (pharmings). |
| **Buffer Overflow** | Estouro de Buffer | Vulnerability occurring when a program writes more data to a memory buffer than it can hold, overwriting adjacent memory spaces. |
| **Cross-Site Scripting (XSS)** | XSS (Scripting Entre Sites) | Injecting malicious client-side scripts into web pages viewed by other users. |
| **NIST Cybersecurity Framework (CSF)** | NIST CSF | Flexible, risk-based cybersecurity standard structured into 6 functions: Govern, Identify, Protect, Detect, Respond, Recover (updated to CSF 2.0 in 2024). |
| **NetFlow** | NetFlow | Network protocol developed by Cisco for collecting IP traffic information and monitoring network flow data. |

### Week 7: Asset Protection, BCP, Policies & Incident Response
**Semana 7: Proteção de Ativos, BCP, Políticas e Resposta a Incidentes**

- **Focus Domains:** Domain 4.0: Security Operations, Domain 5.0: Security Program Management and Oversight (20%)
- **Chapters Covered:** Chapter 9: Implementing Controls to Protect Assets, Chapter 11: Implementing Policies (Incident Response & Threat Hunting)

#### Weekly Objective / Objetivo
Differentiate physical controls, hardware asset management, and backup topologies. Master Business Continuity Plan (BCP) elements (BIA, RTO, RPO, disaster recovery exercises). Understand incident response (IR) plans, processes, and proactive threat hunting.

#### Daily Study Schedule / Cronograma Diario

- **Monday:** Read Chapter 9: Physical security controls (access badges, vestibules, perimeter security, sensors).
- **Tuesday:** Study Asset Management and Backup Strategies (image backups, frequency, testing, geographic considerations).
- **Wednesday:** Study Business Impact Analysis (BIA) concepts (RTO, RPO, MTBF, MTTR, continuity of operations).
- **Thursday:** Study Disaster Recovery Plan (DRP) testing methods (tabletop, simulations, parallel, fail over).
- **Friday:** Read Chapter 11: Incident Response Plan (IRP), communication plan, Incident Response Process (Preparation, Detection, Containment, Eradication, Recovery, Lessons Learned), and Threat Hunting.
- **Saturday:** Weekly Review: Drill physical controls, BCP metrics, and the 6 steps of the Incident Response Process. Practice Week 7 Flashcards.
- **Sunday:** Rest day / Catch-up day.

#### Bilingual Key Glossary

| Term (English) | Traducao | Definition / Descricao |
| :--- | :--- | :--- |
| **Recovery Time Objective (RTO)** | Objetivo de Tempo de Recuperação | The maximum acceptable amount of time a system can be down before causing critical impact. |
| **Recovery Point Objective (RPO)** | Objetivo de Ponto de Recuperação | The maximum targeted period in which data might be lost due to a major incident (determines backup frequency). |
| **Incident Response Process** | Processo de Resposta a Incidentes | Standard 6-step lifecycle: Preparation, Identification, Containment, Eradication, Recovery, Lessons Learned (PICERL). |
| **Threat Hunting** | Caça a Ameaças / Threat Hunting | Proactive process of searching across networks/endpoints to detect malicious activities that evaded existing security systems. |
| **Tabletop Exercise** | Exercício de Mesa / Tabletop | Discussion-based simulation where security team members talk through their roles in response to an emergency scenario. |
| **Access Control Vestibule (Man-trap)** | Eclusa de Segurança / Controle de Acesso | Physical security mechanism consisting of two interlocking doors, preventing tailgating/piggybacking. |
